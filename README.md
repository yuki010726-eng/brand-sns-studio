# 브랜드 SNS 스튜디오

상품을 고르고 주제를 적으면 → 채널별 글귀를 문서화하고 → 이미지를 만들고 → 템플릿에서 카드뉴스를 완성하는 SNS 게시물 제작 도구.

## 실행

빌드 도구 없이 동작하는 정적 사이트지만, ES 모듈을 쓰기 때문에 `file://` 로는 열리지 않는다. 로컬 서버로 실행할 것.

```bash
python -m http.server 5610 --directory brand-sns-studio
```

이후 http://localhost:5610 접속. (Claude Code 에서는 `.claude/launch.json` 의 `brand-sns-studio` 설정으로 자동 실행된다.)

## 새 컴퓨터에서 시작하기

필요한 것은 **Claude Code + GitHub CLI + Python** 세 개다. 순서대로 하면 된다.

### 1. 설치

```bash
winget install --id GitHub.cli
```

Claude Code는 https://claude.ai/download 에서 받거나 `npm i -g @anthropic-ai/claude-code`.
Python은 `python --version`으로 확인하고, 없으면 https://www.python.org/downloads/ 에서 설치한다
(설치 시 **Add Python to PATH** 체크).

### 2. GitHub 로그인

```bash
gh auth login
```

`GitHub.com` → `HTTPS` → `Yes` → `Login with a web browser` 순서로 고른다.

### 3. 저장소 받기

```bash
gh repo clone yuki010726-eng/brand-sns-studio
```

저장소는 **Private**이라 로그인이 되어 있어야 받아진다.

### 4. 실행

`serve.cmd`를 더블클릭하거나:

```bash
python -m http.server 5610
```

http://localhost:5610 접속. Claude Code에서는 `.claude/launch.json`이 등록돼 있어
`brand-sns-studio` 설정으로 바로 띄울 수 있다.
`python`이 없고 `py`만 있으면 `launch.json`의 `runtimeExecutable`을 `py`로 바꾼다.

ES 모듈을 쓰므로 `file://`로 직접 열면 동작하지 않는다. 반드시 서버로 띄운다.

### 따라오지 않는 것 (브라우저에 저장되는 값)

파일이 아니라 브라우저 안에 있어서 컴퓨터를 옮기면 사라진다. 모두 새 컴퓨터에서 다시 만들면 된다.

> **로그인해 두면 글은 따라온다.** 승인된 계정으로 로그인하면 상품·주제·톤·글귀·템플릿 설정과
> 보관함 목록이 서버에 저장돼 다른 PC 에서 이어진다(`lib/sync.js`).
> 아래 표는 **로그인하지 않았을 때**, 그리고 **그림·키처럼 끝까지 안 따라오는 것**을 정리한 것이다.

| 값 | 저장 위치 | 복구 방법 |
|---|---|---|
| 선택한 상품·주제·톤·글귀 | localStorage | 로그인하면 따라온다 · 아니면 1~2단계를 다시 진행 |
| 템플릿 선택·강조 색상 | localStorage | 로그인하면 따라온다 · 아니면 3단계에서 다시 선택 |
| 카드 이미지 | IndexedDB | 다시 생성하거나 업로드 |
| 보관함 썸네일 | IndexedDB | 불러와서 다시 저장하면 새로 만들어진다 (목록의 글은 따라온다) |
| OpenAI API 키 | localStorage | 3단계 이미지 패널에서 다시 입력 |

**API 키는 의도적으로 파일에 저장하지 않는다.** 새 컴퓨터에서 직접 다시 넣어야 한다.
생성해 둔 카드 이미지가 아깝다면 옮기기 전에 내려받아 두고, 새 컴퓨터에서 업로드하면 된다.

### 1단계(프로필 세팅) 프로필 이미지 만들기

이미지 생성 API는 아직 붙이지 않았다. **영문 프롬프트를 복사해 외부 도구에 붙여 쓴다.**

어워즈형에는 길이 두 가지다.

| | 어떻게 되나 |
|---|---|
| 그냥 프롬프트만 | 프롬프트가 심볼(상패·왕관·메달 …)을 **직접 지어낸다** |
| **로고를 함께 첨부** | 프롬프트가 심볼을 말하지 않는다. **첨부한 로고가 곧 심볼**이고 주변 연출만 지시한다 |

로고를 쓰려면 「로고 내려받기」로 원본을 받아 **프롬프트와 같이** 넣으면 된다.
배치는 일부러 정해 주지 않으므로 같은 로고로도 매번 다른 결과가 나온다.
마음에 안 들면 「다시 뽑기」로 연출을 바꾼다.

> 로고 파일은 `assets/logos/` 에 넣는다. 아직 비어 있으면 화면이 「로고 준비 중」으로 뜨고
> 내려받기 버튼이 비활성된다. 넣는 방법은 그 폴더의 README 참고.

마케터형은 사람 사진이 아니라 **기하학적 마크**를 만든다. 아바타는 목록에서 40px 로도 뜨는데
인물 사진은 그 크기에서 뭉개져 계정이 구분되지 않기 때문이다.

### 2단계(아이디어 문서화) 채널별 화법

채널마다 읽는 방식이 달라 구조를 공유하지 않는다.

| 채널 | 구조 |
|---|---|
| 블로그 | 제목 → **3줄 요약** → 목차 → Q&A 소제목 → 남은 일정 → 반론 → 정리. 문단 사이에 `📷 [이미지 N · 역할]`로 **카드뉴스 6장이 들어갈 자리**를 표시한다. 1,500자 안팎. |
| 인스타 | 후킹 → ①②③ **질문(?)과 답(습니다)을 번갈아** → 반론 → 마무리 → 저장 유도 → 해시태그. 종결이 반복되지 않게 사이에 짧은 명사형 줄을 끼운다. |
| 쓰레드 | **후킹 한 줄** → 발견형 도입 → 흘리는 정보 3줄 → 한발 물러선 단서 → **질문으로 마무리**. 해시태그·계정·CTA를 넣지 않는다(넣으면 광고 티가 나서 톤이 무너진다). |

같은 사실이 요약·본문·덧붙임에 중복되지 않도록 2-gram 겹침 60% 이상이면 걸러낸다
(`similarity()`). 한국어는 어미가 바뀌어서 부분 문자열 비교로는 못 잡는다.

### 주제가 글의 중심이 되는 방식

주제를 넣으면 **모델이 그 주제를 3가지로 쪼개는 것부터** 한다(`lib/outline.js`).
상품 자료는 그 이야기를 뒷받침하는 근거로만 쓴다. 그래서 같은 상품이라도
주제가 다르면 소제목·본문·카드 문구가 전부 달라진다.

```
아웃라인 1회 → 블로그·인스타·쓰레드 3회 (같은 뼈대) → 카드뉴스도 같은 뼈대
```

뼈대를 한 번만 만들어 나눠 주는 이유는 세 채널이 같은 내용을 말해야 하기 때문이다.
채널마다 알아서 쪼개게 두면 셋이 다른 이야기를 한다.

**카드뉴스는 아이디어 문서화를 따라간다.** 글귀를 다시 뽑으면 카드 문구도 같이 바뀐다.

### 카드 글자 수는 처음부터 제한된다

카드에 들어가는 문구는 슬롯마다 글자 수 상한이 있다(`lib/templates.js`).
**렌더러로 실측해서 정한 값**이고, 기준은 '잘리기 직전'이 아니라
**'글자 크기가 줄지 않는 지점'** 이다. 크기가 줄면 레퍼런스의 행간이 무너지기 때문이다.

상한은 **처음 만들어 주는 문구에만** 적용된다. 직접 더 길게 써도 막지 않는다.
대신 카드에 다 안 들어가면 미리보기 아래에 **어느 칸이 잘렸는지** 바로 알려 준다.

### 글귀 생성기 교체 지점

`lib/copywriter.js` 의 `generate(channelId, ctx)` 가 유일한 생성 진입점이다.
PART 2에서 실제 AI API로 바꿀 때 이 함수만 교체하면 `pages/copy.js` 는 수정하지 않아도 된다.
`findBanned(text, banned)` 는 편집 중에도 매 입력마다 호출되므로 동기 함수로 유지할 것.

### 3단계(카드뉴스 템플릿) 사용법

**템플릿 3종 중 하나를 고르고**, 그 아래에서 카드 6장을 탭으로 넘기며 한 장씩 편집한다.
왼쪽은 1080×1350(4:5) 미리보기, 오른쪽은 슬롯별 입력칸이다.
문구는 시스템이 미리 채워 두고, 고치면 미리보기에 바로 반영된다.

| 템플릿 | 참고 계정 | 특징 |
|---|---|---|
| A 매거진형 | ai.brief.kr | 하단 검정 그라데이션 · 흰 제목 + **형광색 강조줄** · 상단 중앙 계정명 |
| B 카드형 | soosangmarket | 파랑 그라데이션 · 본문은 파란 박스(대주제, 가운데 정렬) + 흰 박스(소주제) · 마무리는 파랑 단색 팔로우 유도 |
| C 노트형 | sslmo.lab | 종이 배경 · 아이콘 + 아주 굵은 검은 제목 + 회색 본문 · **검정 하이라이트 바**·번호 박스·강조·이모지로 끊어 읽기 |

템플릿마다 들어가는 글의 자리가 달라서 **입력칸 구성도 자동으로 바뀐다.**
예를 들어 카드형 마무리 장에는 「팔로우 유도 문구」와 계정 아이디만 나온다.
템플릿을 바꿔도 **직접 고친 문구는 그대로 남는다.**

고를 수 있는 것:

- **강조 색상 (매거진형)** — 형광 초록·노랑·오렌지·레드·시안·화이트 + 직접 입력(hex)
- **우상단 마크 (카드형)** — 별표·반짝임·별·점·십자 + 🔥 💡 ✅ 👉 + 없음
- **본문 서식 (노트형)** — 입력칸 아래 버튼으로 강조·하이라이트 바·번호 목록·이모지를 바로 삽입

매거진형 문구는 **핵심 한 문장만** 자동으로 뽑아 두 줄로 나눈다(뒷줄이 형광색).
카드에 글이 많으면 행간이 무너지기 때문이다. 더 넣고 싶으면 직접 쓰면 된다.

**이미지는 없어도 된다.** 미리보기 아래 이미지 패널에서 만들거나 올리면 쓰이고,
없으면 템플릿 기본 배경으로 그린다. 이 화면에서 직접 올릴 수도 있어서
**API 키 없이도 끝까지 쓸 수 있다.**
노트형에서는 이미지가 배경이 아니라 **아이콘 자리**에 들어간다.

저장은 「이 카드 저장」과 「6장 모두 저장」 두 가지다.
전체 저장은 브라우저가 연속 다운로드를 막지 않도록 350ms 간격을 둔다.

편집본은 localStorage 에 남고, 상품·주제·톤·템플릿이 바뀌어도 말없이 덮어쓰지 않는다
(편집한 적이 없을 때만 조용히 새 추천 문구로 맞춘다 — 2단계와 같은 규칙).

### 보관함 사용법

4단계 아래 「보관함에 저장」을 누른 게시물만 보관함에 들어간다. **자동으로 쌓이지 않는다.**
같은 상품·주제를 다시 저장하면 새 항목이 생기지 않고 덮어쓴다(덮기 전에 물어본다).

보관함에서는 **주제·상품명·글 내용**으로 검색하고, 상품으로 거르고,
최근 저장순·오래된순·주제 이름순으로 정렬한다.
「불러오기」를 누르면 글귀·템플릿·카드 문구가 그대로 되살아나 4단계로 간다.
작업 중이던 게시물이 아직 보관되지 않았으면 먼저 물어본다.

| 담기는 것 | 안 담기는 것 |
|---|---|

### 어느 AI 모델을 쓸지 고르기

모델 단가가 25배까지 차이 나서 감으로 고르면 손해다. 비교 도구를 붙여 뒀다.

```
http://localhost:5610/tools/bench.html
```

같은 주제를 모델별로 여러 번 돌려 **검수 1회 통과율**과 **실제 지불액**을 잰다.
싼 모델은 반려되면 최대 3회까지 다시 부르므로, 통과율이 낮으면 가격 이점도 함께 사라진다.
그래서 추천은 **통과율 70% 이상 · 폴백 0건**을 넘긴 것 중 가장 싼 모델로 정한다.

앱의 3단계 「AI 설정」에 넣어 둔 키를 그대로 쓴다. **실제 요금이 청구되므로** 시작 전에
예상 비용을 보여주고 확인을 받는다. 처음에는 회차 2~3으로 감을 잡는 것이 좋다.

### 운영 방식 — 배포하지 않는다

**인터넷에 올리지 않는다.** 쓰는 사람이 각자 자기 PC 에서 `serve.cmd` 로 띄워 쓴다
(요청자 결정 2026-08-10). 관계자만 쓰기 때문에 도메인도, 새 주소 등록도 필요 없다.

그래서 각자 필요한 것은 셋이다.

1. 저장소 받기 (Private — GitHub 로그인 필요) · Python
2. **관리자 승인** — 가입만으로는 못 들어간다. 승인 절차는 `SUPABASE_SETUP.md` 의
   「관계자를 새로 붙일 때」를 볼 것. 승인 화면은 앱에 없고 Supabase 대시보드에서 바꾼다.
3. **자기 OpenAI API 키** — 요금도 각자 낸다

글·보관함은 로그인하면 기기 간에 따라온다. 이미지와 API 키는 따라오지 않는다.

## API 키 취급 (중요)

**API 키는 쓰는 사람이 각자 발급받아 각자 넣는다.** 코드·저장소에는 키가 없다.

- 넣는 곳: 2단계 「AI 켜기」 또는 3단계 이미지 패널. **같은 키 하나**로 둘 다 된다.
- 저장 위치: 그 브라우저의 `localStorage`(`bboggl.openai-key`)뿐이다.
- 발급: 입력칸 아래 「OpenAI API 키 발급」 링크를 누르면 바로 발급 페이지로 간다.
  (https://platform.openai.com/api-keys)
- 요금: 각자 자기 키로 결제한다. OpenAI 대시보드의 **Usage limits**로 월 상한을 걸어 두면 좋다.

글귀 모델은 **Terra 이상만** 쓴다. 블로그 형식 지시가 촘촘해서 저가 모델은 검수에 걸려
재시도가 늘고, 그러면 가격 이점도 함께 사라지기 때문이다.

> ⚠️ 키는 그 브라우저에 남는다. **공용 PC에서는 다 쓰고 「키 삭제」를 누를 것.**

키가 없어도 앱은 전부 동작한다. 규칙 기반으로 글이 만들어지고,
이미지는 프롬프트를 복사해 외부 도구에서 뽑아 업로드하면 된다.

### 서버 프록시는 지금 쓰지 않는다

`api/`와 `lib/serverapi.js`에 공용 키를 서버에 두는 방식이 만들어져 있지만,
개인 키 방식으로 정해서 **연결을 끊어 뒀다.** 되돌릴 때를 위해 코드와 `DEPLOY.md`는 남겨 뒀다.
Vercel에 `OPENAI_API_KEY`를 넣지 않으면 그 엔드포인트는 503만 돌려주므로 요금이 나가지 않는다.

## 접근성 규칙

- 모든 버튼에 `aria-label`, 아이콘은 `aria-hidden="true"`
- 본문 텍스트 명도 대비 4.5:1 이상 (`--sub-strong` 은 흰 배경 5.43:1 / 회색 배경 4.92:1)
- `:focus-visible` 3px 아웃라인, 시각적으로 숨긴 radio/checkbox 도 label 에 포커스링 전달
- 본문 바로가기 링크, `aria-live` 토스트, `prefers-reduced-motion` 대응
